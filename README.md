## What it does
Reads mathematical expressions from `input.txt`, evaluates each one using a
stack-based algorithm, and writes the results to `output.txt` in the same
layout (results replace expressions; separator lines are kept).

## Input format
- One expression per line.
- Expressions are separated by a line containing only a separator, e.g. `-----`
  (three or more repeated `-`, `=`, `_`, `~` or `#`).
- Supported: `+  -  *  /`, parentheses, decimals, unary minus (e.g. `-5`, `3 * -2`), optional spaces.

```
3 + 5 * 2
-----
(8 / 4) + 7 * 2
-----
10 - (2 + 3) * 4
```

## Output format
Each result sits on the line where its expression was; separators are copied unchanged.

```
13
-----
16
-----
-10
```

## How it works
Two stacks are used (a variation of Dijkstra's shunting-yard algorithm):
1. **Value stack** – numbers and partial results.
2. **Operator stack** – operators and `(` markers.

When an operator arrives, any operator on top of the stack with equal or higher
precedence is applied first (`*` and `/` before `+` and `-`; left-to-right for
equal precedence). `)` applies operators back to the matching `(`.

## Assumptions and limitations
- **Note on the assignment sheet:** the sample output shows `17` for
  `(8 / 4) + 7 * 2`, but the correct value is `(8/4) + 14 = 16`. The program
  outputs `16`. The other two sample results (`13`, `-10`) match exactly.
- Whole-number results print as integers (`13`); others as decimals (`3.5`), rounded to 6 places.
- Invalid expressions (e.g. `5 / 0`, `(3 + 4`) do not crash the program; that line
  becomes `Error: <reason>` and processing continues.
- Not supported: exponent (`^`), modulo, functions, variables.
- Blank lines in the input are kept as blank lines in the output.
